## Why

Getting Browzy from "extension loaded" to "first answer" is a six-step manual procedure — install Node, clone, run the installer, load the unpacked extension, restart the browser, then configure a provider and test it (`docs/cai-dat.md:21-78`, `host/agent/installer/core.js:182-212`) — and the product only picks the user up at step 6. From there the flow is spread across three surfaces that each restate the same instruction in different words and neither of which shows the order:

- **The side panel lies about being ready.** Opening the panel with nothing configured renders the greeting `Sẵn sàng trên trang này` / `Chào bạn, tôi có thể giúp gì?` plus three suggestion cards (`extension/sidepanel/sidepanel.js:2850-2872`), then puts the actual blocker in a one-line strip *below* it, above the composer (`sidepanel.js:376-434`, mounted at `sidepanel.html:56`). The three suggestions insert prompts that cannot run, because the send path is gated on a complete profile (`test/sidepanel-readiness-states.test.mjs` header; `panel-controller.js:832-834`). The panel is the first thing a new user sees and it claims readiness in its largest text on screen.
- **The settings page is one uninterrupted scroll with nothing closed and nothing ordered.** Four sections, zero collapsible (`grep` for `<details>`/`aria-expanded` in `extension/settings/settings.html`: no section-level toggle exists — the only two `aria-expanded` controls are the theme menu and the manual-model-add form). The one section that blocks progress, `Nhà cung cấp`, is a single `.field-group` of six items in which the optional, advanced **Jev browser tools** block (`settings.html:367-442`, ~76 lines, one 4-sentence notice plus two sub-groups plus its own test and Save) sits *between* the fields a first-run user must fill and the row holding `Lưu` / `Kiểm tra kết nối` (`settings.html:443-449`). To save, a first-run user scrolls past the most advanced content on the page.
- **The page's own orientation copy is wrong.** The status card's not-configured state says `Nhập Base URL, API key và ít nhất một mô hình ở mục Nhà cung cấp bên dưới.` (`extension/settings/settings-app.js:478`) — models are not in `Nhà cung cấp`, they are in the next section, `Mô hình`. The first-run banner separately states the same three requirements in longer prose (`settings-app.js:366-370`), so the page says the same thing twice, once incorrectly.

The result is that the two facts a new user needs — *what is left to do* and *in what order* — are never stated once, plainly. The `agent-settings` spec already requires the Jev browser-tools block to be "a dedicated, opt-in Settings section that is separate from the profile's primary provider configuration" (`openspec/specs/agent-settings/spec.md:185`); today it ships as an anonymous item inside the primary provider group, so the ordering problem is also a spec deviation.

## What Changes

- **One ordered walkthrough, derived from state that already exists.** A new pure module `extension/setup-walkthrough.js` turns the three preconditions the product already enforces — a credential (API key or ChatGPT sign-in), at least one model with a default, and a passing connection test (`extension/settings/connection-gate.js:64-88`) — into one ordered list, each step marked done, in progress, or still to do. It is shared by the settings page and the side panel, so the two surfaces cannot describe the setup differently. No new wire operation, no new controller state, no new companion field: the inputs are `hasCredential`, `chatgptSessionState`, `models`, `defaultModelId`, `connectionStatus`, which of the page's own actions are in flight, and — on the panel only, which is the only surface that can determine it — whether the companion is registered. A companion that is known to be unregistered leads the list and makes the profile not-ready, which is what stops a stale cached profile from being presented as ready on a machine that cannot run anything.
- **The settings page gets a setup card that names the flow**, replacing the two surfaces that restate it today: the first-run banner (`renderBanner`'s `isFirstRun` branch, `settings-app.js:362-371`) and the status card's instruction line. The card shows the headline state plus the ordered steps with a per-step done / in progress / still-to-do carrier and a link that opens the section that step lives in. The `agent-settings` obligation that first-run explains that usage and billing depend on the configured provider (`openspec/specs/agent-settings/spec.md:131`) and the cost disclosure on the test controls are both kept — trimmed, not dropped.
- **Every settings section becomes collapsible**, using this codebase's own disclosure idiom — a real `<button>` carrying `aria-expanded` + `aria-controls` over a body that stays in the DOM with `hidden` (`extension/ui/behaviors.js:141-142`, `extension/sidepanel/sidepanel.js:2721-2722`, `sidepanel.css:949-952`) — never `<details>`, which within `extension/**` appears only in raw-payload debug surfaces (`extension/recorder/options.js`, `extension/sidepanel/run-feedback.js`) and in neither settings page. A section that still has an unmet step, or that holds an error, is NOT allowed to start collapsed, so collapsing cannot hide a failure. This is a deliberate, bounded exception to the earlier redesign's "no section hidden behind a pane" rule (`openspec/changes/redesign-settings-typed-only-skills/design.md` D6): a collapsed section keeps its heading, its state label and its expander on screen and is purely user-controlled, which is what a long scroll needs, whereas a pane tab makes the other sections unfindable.
- **Jev browser tools becomes its own top-level section, placed after the provider connection row**, satisfying the separation the `agent-settings` spec already requires and taking ~74 lines of advanced, optional configuration out of the first-run path. It starts collapsed, and its heading carries a state label (`Chưa bật` / `Đã lưu khoá`) so its condition is readable without opening it.
- **Deep links keep working, and now reveal what they point at.** `settings.html#btn-test-connection` is a documented destination — the panel's own re-test actions open it (`extension/sidepanel/sidepanel.js:362-368`, pinned by `test/sidepanel-readiness-states.test.mjs:324`) — and `#section-models` is the gate hint's jump target (`settings-app.js:449-455`, pinned by `test/settings-connection-gate.test.mjs:233`). A hash pointing inside a collapsed section expands that section before scrolling, or a link that says "chọn một mô hình ở mục Mô hình" would land on a closed drawer.
- **Copy is trimmed, not weakened, across the onboarding surfaces**: duplicated restatements and developer-facing asides go; every claim that is a truthfulness obligation stays (cost/usage, the ChatGPT unofficial-backend and OpenAI-terms disclosure, where the secret is stored, that saved is not the same as tested).
- **The side panel stops claiming readiness it does not have.** When the profile is not ready and there is no transcript, the empty state shows the same walkthrough instead of the greeting and the three unusable suggestions, and the composer-adjacent strip that repeats the same sentence is suppressed for that case only. With a transcript present (readiness can regress mid-conversation) the strip is unchanged.

Not a behavioral change to persistence, the wire protocol, validation, or any host code: this change is `extension/settings/**` presentation, one new shared pure module, `extension/sidepanel/**` pre-setup presentation, and the tests that pin them.

## Capabilities

### New Capabilities

(none — the walkthrough is presentation over state the `agent-settings` and `browser-assistant-panel` capabilities already define)

### Modified Capabilities

- `agent-settings`: adds a "Setup walkthrough on the settings page" requirement — the page names the next unmet setup step and its order, keeps every section's controls reachable through a collapsible section, never presents a section collapsed while it holds an error the user must act on (a merely-unsatisfied step remains the user's to collapse, because the walkthrough naming it is never collapsed), reveals the section a deep link targets, and keeps the Jev browser-tools section visually separate from the primary provider configuration.
- `browser-assistant-panel`: adds a "Pre-setup panel guidance" requirement — while the profile is not ready and no transcript exists, the panel names the unmet step and links to the control that resolves it, and per-readiness claims of readiness are not made.

## Impact

- **Extension (new)**: `extension/setup-walkthrough.js` — pure, imported by both the settings page and the side panel; no `document`, no `chrome.*`.
- **Extension (modified)**: `extension/settings/settings.html` (each section wrapped in a heading-button + body, Jev browser tools moved to its own section after the provider connection row, first-run banner removed from the markup's render path), `extension/settings/settings-app.js` (setup card renders the walkthrough; section open/close binding; deep-link reveal), `extension/settings/settings-sections.js` (new pure module: default open state, override precedence, which section owns which control), `extension/sidepanel/sidepanel.js` (readiness-aware empty state; suppress the duplicate strip when the empty state carries the message), `extension/sidepanel/sidepanel.css` (styles for the walkthrough rows, using existing tokens only).
- **Extension (untouched by rule)**: `extension/ui/**` — `tokens.css`, `components.css`, `base.css`, `behaviors.js`, `icons.js`, `prose.css` are consumed, never edited (`openspec/ui-dna.md`). All new styling is page-local `<style>`, using existing tokens only. No new palette, no new spacing scale, no font change.
- **Host (untouched)**: no change to `host/**`. No new operation, no protocol change, no stored-field change.
- **Tests (new)**: `test/setup-walkthrough.test.mjs` (step derivation and its precedence, cross-checked against `connectionGate()`), `test/settings-sections.test.mjs` (default open state per state, override precedence, an error forces its section open, control→section map covers every deep-linked control and every mapped id exists in the markup), `test/sidepanel-setup-walkthrough.test.mjs` (the panel's pre-setup empty state, executed from the shipped source via `test/_extract.mjs` with its dependencies injected — the technique this repository already uses for the DOM layers that cannot be imported in Node).
- **Tests (modified)**: `test/settings-connection-gate.test.mjs` (the status-card renderer is renamed and the card gains the walkthrough; the seam assertions it makes — one `connectionGate()` call, computed before the provider renderer, one disabled assignment per test button, the `#test-gate-hint` container, the `#section-models` jump target — must all keep holding), plus whichever of the settings/panel suites the source-level pins require; the pin inventory is enumerated in `design.md` under "Constraints from existing tests".
- **Copy (modified)**: Vietnamese strings in `settings.html`, `settings-app.js`, `sidepanel.js` and the new module. No user-visible string is added in English.
