# Proposal: Jev step decisions that reason before they act

## Why

A TypeSafe (Jev) run reaches the page through a good element selector and a decision model that is never allowed to think, over an observation that cannot see half the page's controls. Four properties of the current cycle produce the behaviour the operator reports — the run "clicks whatever it is asked to click" and never reconsiders, where the same goal on an `anthropic` or `chatgpt` profile is carried out competently:

1. **The decision call is wired as a value-filler, not as an agent turn.** Every configured-model call — the step decision included — is sent with the reference's text-value parameters: `reasoning: {effort: "low"}`, or `thinking: {type: "disabled"}` on a DeepSeek host, and `max_tokens: 1024` (`host/agent/jev/text-helper.js:330`). The one call that carries the whole run's judgment is the one call with reasoning switched off.

2. **The decision is made blind.** The step decision's context is `{goal, memory, page{url, title, text}, recent_actions}` (`text-helper.js:963`). The element table that the same observation already produced for Jev is never shown to the model that decides the step, so the intent it writes ("the Search button") is a guess about a page it has only read as prose. When no such control exists, the model has no way to know, and still emits a step.

3. **Selection is forced to answer, and its doubt is discarded.** `TARGET_SELECTION` instructs "if none matches, choose the closest offered key" (`text-helper.js`), so a blind intent always resolves to *something*. The validated `confidence` and target probability that come back are recorded on the step (`runtime.js:926`) and used for nothing. A near-random pick is dispatched with the same authority as a certain one — literally "hỏi đâu click đấy".

4. **Half the page is invisible to both models.** `extension/content.js:351-359` `isInteractive()` admits an element only when it is a native control, declares an ARIA role from a fixed list, has `tabIndex >= 0`, an inline `onclick`, or `contenteditable`. A framework-rendered suggestion row or custom option — a plain `<div>`/`<li>` with a delegated listener and a pointer cursor — matches none of them and never enters the observation. The loop then re-types or re-clicks the one control it can see, and the transcript reads like a reasoning failure. Upstream hit the same blind spot (browser-use/jev-ultrafast issue #23: 60 identical `TYPE_TEXT` actions), and the run's own post-typing behaviour compounds it — the next observation is taken immediately after typing, before an autocomplete list has rendered.

5. **The decision model is cut off from the providers the project already supports.** Everywhere else this product speaks one model language: an `anthropic` profile resolves to the real Anthropic endpoint, a `chatgpt` profile to the companion's local gateway that translates `POST /v1/messages` to the Codex upstream (`host/agent/chatgpt/gateway.js:417`). A `typesafe` profile alone reaches its decision model over a second, OpenAI-shaped wire (`{textModel.baseUrl}/chat/completions`) with a second credential — inherited from the reference implementation, never chosen for this project. So the one call that carries the run's judgment cannot use an Anthropic key or a ChatGPT subscription the operator already has, and demands a third-party API key instead.

Nothing here is a defect of the labour split pinned by `2026-09-18-add-jev-run-context` (the configured model decides every step; Jev selects the element). The split is kept exactly as it is. What this change fixes is the *inputs and outputs* of the decision call: it may think, it may see the controls it is deciding among, it must say what the previous step accomplished, and Jev is allowed to say "none of these".

## What Changes

- **Jev gains OpenRouter as a third source.** Jev speaks its own decision protocol — `state` plus typed `questions` — and is never reachable through a chat-completion or Messages port; the existing source abstraction (`typesafe` → `/v1/systemone`, `vercel` → `/v4/ai/evaluation-model` with its own headers and confidence placement) gains `openrouter` → `POST /api/alpha/decisions`, carrying the model id in the body. One validated decision shape, one retry policy, one taxonomy across all three; the route is published as alpha and is labeled as such where it is selected.
- **The decision model speaks the project's own standard.** A `typesafe` profile's decision model becomes a choice of source: an Anthropic endpoint and key, the ChatGPT subscription through the existing companion gateway, or today's OpenAI-compatible text model (kept, so a local model or OpenRouter stays usable). The first two are reached with one direct `POST /v1/messages` through the loop's own request helper — no tools, no MCP, no conversation, one turn — the same wire the companion's ChatGPT gateway already speaks. Jev's own `POST /v1/systemone` is untouched, the `typesafe:jev` identity marker on the snapshot env stays exactly as it is, and credentials, the capability test's stages, and the settings disclosure follow the selected source.
- **Reasoning budget follows the call's job.** The decision-class calls — the step decision, the run plan, memory revisions, stall recovery, and the completion check — SHALL be sent with a deliberate reasoning effort (`medium`) instead of the value-filler parameters; DeepSeek hosts get their thinking switch enabled rather than `disabled`. The capability test's probes keep the cheap parameters. `max_tokens` for the step decision rises to hold a short evaluation beside the decision.
- **The step decision sees the controls.** The step-decision context gains a bounded, numbered projection of the same observed element table Jev is offered — tag/role, label, current value, disabled/checked state — under its own size budget with the same deterministic tail-dropping and disclosure the selection request already uses. The table is *context only*: the decision still names its element in plain language and Jev still resolves it. The instruction gains the rule that follows from it — an intent must name a control the table actually offers, and when none does, the step is `SCROLL_*`, `WAIT`, `NAVIGATE`, or `BLOCKED` instead of a fabricated intent.
- **Every step evaluates the one before it.** The step-decision answer gains one required bounded field, `evaluation`: what the previous action was supposed to achieve and whether the current observation shows it did (for the first step of a run, the starting position). The validator accepts it as a fifth key and bounds it; the field is recorded on the step and shown in the run's row list. Recent-step rows carry the element that was actually operated and the step's outcome (executed, skipped with its reason, denied) so the evaluation is grounded in what happened rather than in what was intended.
- **The observation lists controls that are operable in fact.** `page_snapshot` gains a conservative second pass: a rendered element intersecting the viewport with a computed pointer cursor is listed, innermost-only, capped by its own bound, and counted in the existing omission disclosure. This is the one change that reaches beyond the Jev loop — every runtime observes through the same operation — and it is the highest-value item in the change.
- **A cycle that follows typing settles before it observes.** Bounded by a short fixed ceiling, the run waits for the controls the typing revealed and observes as soon as they appear; nothing else about the cycle changes.
- **The snapshot marks what just appeared.** The per-document newly-appeared marking the runtime's other reads already carry (`2026-09-12-mark-new-page-elements`) is put on the snapshot's element record and carried into both the decision's element table and the selection request's state, with one sentence in each instruction saying what it means: a control that just appeared is very likely what the previous action revealed. No second marking is computed.
- **Jev may abstain.** `TARGET_SELECTION` stops instructing a closest-key fallback; it instructs that a selection is made only when an offered element genuinely matches the intent. A validated answer the run judges unresolved — a reported confidence below a fixed floor, or a top-two probability margin below a fixed epsilon on any source — SHALL NOT dispatch: the step is recorded skipped with the existing `target_unresolved` reason, carrying the confidence that caused it, counts one toward the no-progress bound as that path already does, and the loop continues with the skip visible to the next decision.

No change to the provider/labour split, Jev's own wire protocol, the answer-validation rules, the dispatch discipline (approval cards, lease, tab scope, host-side checks), the run bounds, or the `anthropic`/`chatgpt` runtimes. The settings and credential surfaces change only where the decision-model source requires it, and a profile that keeps the OpenAI-compatible text model keeps today's fields and behaviour. No new settings surface: the reasoning effort is a fixed property of the call, and the latency it costs is stated in the design rather than exposed as a knob.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `agent-browser-runtime`: `page_snapshot` lists controls that are operable in fact — a conservative, innermost-only, capped pointer-affordance pass beside the existing markup tests — so delegated-listener controls stop being invisible to every runtime.
- `typesafe-jev-provider`: OpenRouter joins TypeSafe and the Vercel gateway as a Jev source, on Jev's own decision protocol; the observation settles after typing and marks elements new since the previous observation; the step decision gains an observed-element table in its context, a required evaluation field in its answer, and a deliberate reasoning budget; element selection gains a confidence floor and an honest abstain that routes to the existing target-unresolved skip instead of dispatching a low-confidence pick.
- `agent-settings`: a `typesafe` profile configures its decision-model source (Anthropic endpoint, ChatGPT subscription, or OpenAI-compatible text model); the required fields, the credential actions, the connection test's stages, and the disclosure of what is sent where all follow that choice.
- `browser-assistant-panel`: a step row shows the decision's evaluation and, for an abstained step, the confidence that caused the skip.

## Non-goals

Deliberately out of scope, recorded so they are not re-litigated mid-implementation: multi-action batching per cycle (a latency win that conflicts with the per-dispatch approval gate), a page-state triage classifier (login wall / CAPTCHA / paywall), restructuring the completion check into a per-requirement checklist, a cold-start re-observation guard, and any settings surface for the reasoning effort, the confidence floor, or the table bounds. The first four are worth doing and belong in their own changes; the last is rejected on principle in the design.

## Impact

- `extension/content.js` — the snapshot's element record gains the existing newly-appeared marking (~line 1310, the watermark `find`/`isNew` already uses); `isInteractive()` gains the pointer-affordance pass (innermost-only, capped, counted in the omission disclosure); the snapshot's element table grows on pages that need it and is unchanged on pages that do not. The extension is a service worker + content script: no effect until it is reloaded.
- `host/agent/jev/runtime.js` — the bounded post-`TYPE_TEXT` settle before the next observation, and the new-since-last-observation diff over the observation's reference identity.
- `host/agent/jev/client.js` — the `openrouter` source beside `typesafe` and `vercel`: its decision URL, its body (model id in the body), and its response normalization, under the existing shared retry policy and taxonomy.
- `host/agent/jev/text-helper.js` — the decision-class transport gains the Anthropic-standard path (the bounded tool-free `query()` options, thinking blocks read as answer text only, the capture as an image content block) beside the existing Chat Completions path; `NEXT_STEP` instruction and `parseStepDecision` (the new `evaluation` key and its bound), the reasoning-parameter helper (`reasoningParam`, line ~330) split by call class, the step-decision `max_tokens`, the element-table projection in the decision context, `TARGET_SELECTION`'s abstain wording.
- `host/agent/jev/questions.js` — the shared bounded element-table projection and its fitting ladder reused for the decision context; `recentActionRows` gains the operated element and the step outcome.
- `host/agent/jev/runtime.js` — the confidence floor applied to the validated selection, routing to the existing `target_unresolved` skip; the evaluation carried onto the step record.
- `host/agent/settings/profile.js`, `profile-schema.js`, `capability-test.js`, `host/agent/jev/capability.js` — the decision-model source, its credential resolution (Anthropic key target, ChatGPT refresh token + gateway token, or the text-model key), and the capability stages that follow it; `env.ANTHROPIC_BASE_URL` keeps the `typesafe:jev` identity marker and the decision endpoint resolves into its own snapshot field.
- `extension/settings/*` — the source picker, the conditional fields, and the disclosure text.
- `host/agent/protocol.js` — the step record's `evaluation` field and the abstain reason's payload.
- `extension/sidepanel/conversation-model.js`, `extension/sidepanel/tool-labels.js` — the evaluation row and the abstain label.
- Tests: `host/test/jev-text-helper.test.mjs`, `jev-questions.test.mjs`, `jev-runtime.test.mjs`, `jev-client.test.mjs`, `jev-capability.test.mjs`, `agent-typesafe-run.test.mjs`, plus the side-panel conversation-model/tool-label suites.
- Cost and latency: one step decision per cycle now thinks and carries a larger context. This is a deliberate trade against Jev's "ultrafast" pitch, bounded by the existing per-run action and decision ceilings.
