## Why

Browzy's side panel drives exactly one anonymous assistant. Its personality, its model, and the tools it may reach are fixed at build time by `renderBrowserAutomationSystemPrompt()` plus whatever the operator's single provider profile happens to select — there is no way to say "use my careful read-only researcher for this tab" or "use the form-filler that is allowed to click submit but never navigates away". The `Task` tool is already available and auto-approved in every run (`host/agent/tools/query-options.js`, `Task` is in both `tools` and `allowedTools`), and the pinned SDK already accepts programmatic subagent definitions (`Options.agents?: Record<string, AgentDefinition>`, `host/node_modules/@anthropic-ai/claude-agent-sdk/sdk.d.ts:1441`; `AgentDefinition` at `sdk.d.ts:38`) — but `buildIsolatedOptions()` passes no `agents` key at all, so `Task` can only ever spawn the SDK's own built-in general-purpose subagent. The capability is bought and paid for and currently unreachable.

This change makes the operator the author of their agents: a local, app-owned catalog of named agent definitions, each with its own description, system prompt, model, tool allowance, preloaded skills and turn cap; one chosen as the conversation's primary agent in the side panel; the rest reachable by the model through `Task`. It deliberately does this **without** widening the security boundary — an agent definition is a *narrowing* instrument only, and this proposal states that as a checkable requirement rather than a hope.

## What Changes

- **New app-owned agents catalog**, structurally mirroring the existing skills catalog (`host/agent/skills/{paths,catalog-store,frontmatter,import,author,manage,errors,index}.js`): one atomically-written `agents/catalog.json`, one immutable snapshot directory per agent named by its own validated name, the same `NAME_PATTERN` (`^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`) and the same path-traversal rejection at the point of use, and the same "reject, don't guess" posture toward malformed input.
- **Two authoring paths, one record shape.** *Import* reads an `AGENT.md` whose YAML frontmatter carries `name`, `description`, and optionally `model`, `tools`, `skills`, `max-turns`, with the markdown body below the frontmatter as the agent's system prompt. *Author* accepts the same fields directly from the Settings UI. Both produce the identical catalog record and the identical snapshot on disk; neither ever executes anything found in the source folder.
- **`Options.agents` is populated from the enabled catalog** inside `buildIsolatedOptions()` (`host/agent/tools/query-options.js:562`), passed **programmatically**. `settingSources: []` is untouched, and no agent is ever discovered from disk by the SDK — the SDK's own on-disk agent-frontmatter path stays closed, exactly as `strictMcpConfig: true` already closes the equivalent MCP path (`sdk.d.ts:2129` names on-disk agent frontmatter explicitly).
- **Tool allowance is an intersection, computed by this project, never a declaration honoured on trust.** Each emitted `AgentDefinition.tools` is the set intersection of what the agent's record declares and the run's own actual allowance (`qualifiedBrowserToolNames` + `extraToolNames`, i.e. the exact arrays that same call already writes into `tools`/`allowedTools`). Each emitted `AgentDefinition.disallowedTools` always contains `HIGH_RISK_BUILTINS` (`Bash`, `Write`, `Edit`, `NotebookEdit`) written by this project's code. A name in the record that the run does not itself hold is dropped and reported, never forwarded.
- **A per-conversation primary agent**, selected in the side panel and persisted in the conversation's versioned metadata envelope (`host/agent/storage/conversation-metadata.js`), so a reload or a resume restores the same choice. Selecting no agent is a first-class state and is byte-identical to today's behavior.
- **Agent prompts compose, never replace.** An agent's `prompt` is appended to — never substituted for — the run's `renderBrowserAutomationSystemPrompt()` and `renderPageContextSystemPrompt()` output, so no agent can shed the browser-automation contract or the bound page context by being selected.
- **Model resolution is explicit, never silent.** An agent's `model` is resolved against the operator's own profile model catalog (`host/agent/settings/models.js`, `named-profiles.js`); an unresolvable model falls back to the profile's model and the run surfaces a named, visible notice. There is no path where an agent silently runs on a model other than the one its card shows.
- **New `agents_*` wire message kinds** (`agents_list`, `agents_import`, `agents_author`, `agents_refresh`, `agents_enable`, `agents_disable`, `agents_remove`), symmetric with the existing `skills_*` set (`host/agent/companion.js:960-1003`). Purely additive: no existing envelope shape changes, and an older companion already fails closed on an unknown kind with `unknown_message_type` (`host/agent/companion.js:198-202`).
- **New Settings > Agents page**, symmetric with Settings > Skills (`extension/settings/skills.html` + `skills-{app,client,controller}.js`), plus an agent picker in the side panel composer area. Every existing panel accessibility guarantee (WCAG 2.1 AA, usable at 320px, keyboard reachable, polite live region) continues to hold for the new surfaces.
- **Honest usage accounting.** `host/agent/storage/usage-ledger.js` already counts subagent consumption, because it diffs cumulative `modelUsage` (which includes `Task` subagents) rather than the SDK's aggregate `usage` (which excludes them). `modelUsage` is keyed by **model**, not by agent, so per-named-agent cost attribution is not available from the SDK and this change does **not** claim it. That limitation is stated in the spec and on the UI rather than papered over with an invented number.
- **README claims are itemized**, in the same evidenced form the rest of that document uses: what an agent definition can and cannot do, which SDK fields are forwarded, and the explicit statement that agents narrow authority and never widen it.

Not a breaking change. A conversation with no agent selected produces byte-identical `query()` options to today.

## Capabilities

### New Capabilities

- `agent-definitions`: the app-owned catalog of user-defined agents — import/author validation, immutable snapshots and lifecycle, the permission intersection that bounds every emitted definition, model resolution and its fallback, primary-agent selection per conversation, and the management/selection surfaces.

### Modified Capabilities

- `agent-browser-runtime`: "Confined tool execution and browser scope" currently reasons about the single main agent. It must state that a named subagent definition is bounded by the same confinement — it can never add a tool the run does not hold, never reach `HIGH_RISK_BUILTINS`, never widen tab scope or the run upload allowlist, and never bypass `canUseTool`/`authorizeToolCall`.
- `browser-assistant-panel`: gains the primary-agent picker as observable panel behavior — which agent a run used is visible in the transcript, the selection is bound to the conversation, and the picker meets the capability's existing accessibility requirements.

## Impact

- **Host (new)**: `host/agent/agents/` — `paths.js`, `catalog-store.js`, `frontmatter.js`, `import.js`, `author.js`, `manage.js`, `errors.js`, `resolve.js` (intersection + model resolution), `index.js`.
- **Host (modified)**: `host/agent/tools/query-options.js` (`buildIsolatedOptions()` gains an `agents` parameter and emits `Options.agents`), `host/agent/companion.js` (`agents_*` handlers; resolve the conversation's primary agent at run start and pass it through), `host/agent/session/manager.js` + `host/agent/storage/conversation-metadata.js` (persist the per-conversation selection), `host/agent/protocol.js` (validate the new message kinds).
- **Extension (new)**: `extension/settings/agents.html` + `agents-{app,client,controller}.js`, `extension/sidepanel/agents-{client,model}.js` and the picker within `extension/sidepanel/sidepanel.js` / `panel-controller.js`.
- **Tests (new)**: `host/test/` coverage for catalog validation, the tool intersection, the `HIGH_RISK_BUILTINS` floor, model fallback, prompt composition, and the additive protocol shape.
- **Docs**: `README.md` gains an itemized AI Agents section consistent with "What this is not".
- **Explicitly unchanged**: the external-MCP path (`host/tool-runtime.js`, `host/mcp-server.js`, `host/codemode/server-*.js`) stays byte-identical, as the README promises; `HIGH_RISK_BUILTINS` is not widened; `settingSources: []` and `strictMcpConfig: true` are not touched.
- **Concurrent-work hazard**: another session holds uncommitted work in `extension/background.js`, `extension/manifest.json`, `extension/sidepanel/tool-labels.js`, `host/tool-definitions.js`, `host/agent/tools/mapping.js`, `host/package.json`, `host/npm-shrinkwrap.json`, `test/fixtures/registry-baseline.json`, `test/registry-baseline.test.mjs`, `test/registry-sdk-mapping.test.mjs`, `test/webfetch-url-guard.test.mjs`, `extension/webmcp/`, `test/fixtures/webmcp/`. This change is designed to need none of them; `design.md` records how each potential contact point is avoided, and any residual need is a dependency to surface, not a file to edit.
