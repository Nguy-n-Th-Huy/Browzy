# Proposal: Task Memory

## Why

Every run starts from nothing. An operator who asked for "the tender notices with a Hải Phòng location" last week and asks again today watches the agent rediscover the same site from scratch: list the tabs, read the page, search for the filter, click around, read again. The work was done and recorded — the transcript holds every tool call — but nothing reads that record back when the same kind of task comes up on the same site. Workflows (`side-panel-workflows`, `add-workflow-materialization-and-heal`) solve a different problem: an *explicit*, operator-owned, approval-gated definition that is replayed as data. They are the right tool for a fixed procedure, and the wrong one for "just remember how you did it": authoring a workflow is a deliberate act, and most repeated tasks are never worth one. Operator request, 2026-09-24: *"nếu mà làm lại thì nhớ việc làm nhanh chứ không phải đi mò lại — nó sẽ biết làm bước gì"*.

Task memory closes that gap with the smallest honest mechanism: after a run completes, the host derives a bounded, secret-screened record of *what worked on that site for that kind of request*; when a later request on the same site looks like a repeat, the steps that worked are handed to the model as **advice** about the past — never as a plan to replay, never as authority to act. The agent still looks at the live page and still asks for every permission it would have asked for; it just stops exploring things it already knows.

## What Changes

- **A memory is derived by the host from recorded evidence only.** When a run ends in `run_done`, the host reads the run's own trail — the same transcript `tool_use` blocks and Jev `jev_step` events `workflows-materialize.js` already reads — and writes one memory entry: the site, a bounded intent summary of the request, the ordered steps that were actually dispatched (tool, screened arguments, element identity as `role`/`name`), where the run started, and how long it took. The model never writes memory; a run that was stopped, errored, blocked, or drifted writes nothing. There is no memory that is not a record.
- **Secrets never become memory.** Arguments go through the existing `screenTrailArgs` / `looksSecretBearing` / `looksSecretArgKey` screen; typed text keeps the omission the action timeline already applies; a credential-shaped element label is never stored. Any step that cannot be recorded safely is recorded as "a step here was omitted", not guessed.
- **Recall is deterministic and site-bound.** At run start the host matches the request against stored memories for the bound page's host (exact host match through `normalizeHost`), scores intent similarity lexically, and offers at most three candidates above a threshold. No model call, no fuzzy cross-site guessing, and an explicit "làm lại như lần trước" style request is a strong signal, not a bypass.
- **Recall is advisory guidance, never authority.** Recalled steps enter the run as an additive system-prompt section rendered like `renderJevToolsPreferenceSystemPrompt` — into `systemPrompt`, never into the `prompt` — framed as *what worked before, verify against the live page*. For a Jev-driven step the same text reaches the planner as bounded advice; the decision layer still selects fresh actions from the live snapshot. Nothing about `canUseTool`, send/submit gating, per-site decisions, or protected actions changes: a recalled step that would need approval still needs approval.
- **A read-only `task_memory` tool** lets the model pull the full recalled steps mid-run (`recall`, `list`) when the summary is not enough. It has no write action.
- **Memories reinforce, go stale, and are bounded.** A run that used a memory and completed refreshes it; a run that used one and then failed or drifted on that site marks it stale and stops offering it until a later success confirms it again. Per-site and global caps evict least-recently-confirmed entries; size guards reject rather than truncate.
- **The operator owns it.** A settings toggle ("Ghi nhớ cách làm việc", default on); the existing "Không lưu nội dung câu hỏi" privacy control suppresses writing new memories; a management surface lists memories per site and forgets one site or everything; deleting a conversation deletes the memories derived from it.
- **The panel tells the truth about it.** When a run received recalled memory, the run's timeline group shows one distinct disclosure line ("Đã tham khảo cách làm lần trước · <site> · <when>") that is never counted as a browser operation and never presented as a step that was performed.

## Capabilities

### New Capabilities
- `agent-task-memory`: derivation of task memories from completed runs, their record shape and secret screening, bounded per-user storage, deterministic site-bound recall, advisory-only delivery to the model and the Jev planner, the read-only recall tool, reinforcement/staleness/eviction, and the privacy, opt-out, forgetting and deletion rules.

### Modified Capabilities
- `browser-assistant-panel`: a truthful recalled-memory disclosure in the run timeline, and a memory management surface (list per site, forget one site, forget all, empty state).
- `agent-settings`: the task-memory toggle and its relationship to the existing prompt-caching privacy control.

## Impact

- **New host modules**: `host/agent/memory/store.js` (`TaskMemoryStore`: write/list/get/forget/reinforce/markStale, caps and guards), `host/agent/memory/derive.js` (pure derivation from a run's trail, reusing `workflows-materialize.js`'s trail reading and screening), `host/agent/memory/recall.js` (pure matching and scoring, reusing `workflows-match.js`'s host normalization), `host/agent/memory/guidance.js` (the system-prompt section renderer), `host/agent/tools/task-memory.js` (the read-only SDK tool, `TASK_MEMORY_TOOL_NAME`).
- **Modified host files**: `host/agent/storage/paths.js` (`memoryRoot()`, `memoryHostDir(hostHash)`), `host/agent/tools/query-options.js` (accept and append the rendered guidance section beside the Jev preference section), `host/agent/companion.js` (recall at run start, derive on `run_done`, reinforce/stale on the next outcome, register the tool **and** name it in `extraToolNames`, delete on conversation deletion, honour the toggle and the privacy control), `host/agent/jev/runtime.js` / `client.js` (accept bounded advisory text on the plan request), `host/agent/protocol.js` (memory list/forget ops and the toggle), `host/agent/storage/transcript-store.js` (one durable `memory_recalled` event per run so the disclosure survives reconnect).
- **Extension**: `extension/sidepanel/sidepanel.js` + `conversation-model.js` (render the disclosure from the durable event), `extension/sidepanel/tool-labels.js` (one label for `task_memory`), `extension/settings/settings.html` + `settings-client.js` (toggle), `extension/settings/permissions.html` or a sibling page (management surface), `openspec/ui-dna.md` unchanged in spirit: existing tokens, disclosure and status primitives only.
- **Tests**: `host/test/task-memory-derive.test.mjs`, `task-memory-recall.test.mjs`, `task-memory-store.test.mjs`, `task-memory-tool.test.mjs`, `task-memory-guidance.test.mjs`, companion wiring proofs; panel tests for the disclosure and the management surface; a live QA gate on a real repeat of a site task.
- **Unchanged**: the browser tool registry, the workflow registry and its schema, the approval policy and classifier, the recorder, and the wire shape of action events. No new executor: memory is text the model reads, not steps the host performs.
